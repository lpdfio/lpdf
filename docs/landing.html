Why lpdf

Most PDF libraries require coordinate math.
lpdf does not.

Most libraries are single-platform and give you a canvas. You place every element at an explicit x/y position. lpdf gives you a layout engine.

⊞
Layout, not coordinates
Describe your document using stacks, flanks, grids, and frames — the same mental model as CSS flexbox. The engine resolves coordinates for you. Change content size or add a row; the layout adapts automatically.
🌐
One template, every language
The XML template is the portable artifact. Render it natively from Node, .NET, Python, or PHP using the same layout definition. Switch stacks without redesigning your templates. No competitor makes this claim.
🔒
Fully offline
The WASM renderer, visual editor, PDF preview, and codegen all run on the machine. No server, no account, no data leaves the building. Critical for financial, HR, legal, and compliance documents.
The full chain

Five layers. Each one removes a gap left by the previous.

Each layer has standalone value. Together they form a moat that is hard to replicate in isolation.

1
Library
Layout-first rendering
Call the builder API directly in your language. Describe layout with semantic primitives — stack, flank, grid, frame — and let the engine calculate positions. Full control, fully typed, zero coordinate math.
2
XML Format
Portable, diffable template artifact
The layout lives in a schema-validated XML file — readable, version-controllable, and LLM-friendly. The same XML renders correctly on every supported language adapter. This is the "write once, render anywhere" guarantee.
3
Visual Editor
Author inside VS Code, no context switch
Open any lpdf XML in VS Code. A layout preview panel opens beside it — live, synced to the file. Edit visually; the XML updates. Export PDF directly to disk via the WASM renderer. Undo/redo spans both the raw XML and the visual editor.
4
Data Binding
Preview with live data, author with fallbacks
Bind a JSON file to the template. The visual editor substitutes real values, expands loops, and respects conditionals — in real time. Without a JSON file, all inline fallback values are shown, so the template always looks complete and previewable.
5
Codegen
Convert to typed code, at cursor
One command converts the XML template to typed builder code in TypeScript, C#, Python, or PHP — inserted directly at the cursor in the file you are working in. With data binding in the template, the generated code emits real data accessors, not string literals. Nearly production-ready on generation.

Authoring

Three ways to create a template.
All produce the same XML.

Choose the level that matches your workflow. They are not mutually exclusive — start visual, drop into XML when needed, generate code when ready.

Option 1
Programmatic API
// TypeScript — fully typed const doc = kit.document({ size: "a4" }, kit.stack({ gap: "m" }, kit.flank({}, kit.text({ weight: "bold" }, "Invoice"), kit.text({ color: "muted" }, "2026-04-14") ), kit.divider() ) )
Call the builder API directly in your language — TypeScript, C#, Python, or PHP. Fully typed, fits into any existing codebase. No XML required.
Option 2
XML by hand
<lpdf version="1"> <document size="a4"> <pages><page> <stack gap="m"> <flank> <text weight="bold">Invoice</text> <text>2026-04-14</text> </flank> <divider/> </stack> </page></pages> </document> </lpdf>
Write or edit the XML directly. XSD schema gives you autocomplete and validation in any editor. Diffable, version-controllable, and readable by both humans and LLMs.
Option 3
Visual editor in VS Code
Developer opens invoice.xml in VS Code │ ├── XSD autocomplete — no config required ├── CodeLens: "Open in lpdf Editor" │ │ │ └── Layout panel opens beside XML │ ├── Left: live layout preview │ ├── Right: PDF preview (WASM) │ └── "Export PDF" → saves to disk
Open the visual editor from any lpdf XML file. Edit layout visually — the XML stays in sync via VS Code's standard TextEdit API. Undo/redo spans both views. No context switch, no separate app.
Data binding

Preview with live data.
Author with self-documenting fallbacks.

Four attributes cover the entire dynamic layer — no new syntax, no template language bolted on. The template always looks correct whether or not JSON is loaded.

data-value="path"
Render a JSON path value as text content. Inline text is the fallback when no data is loaded.
data-source="path"
Repeat this element for each item in an array. Children defined inside are the single sample row when no data is loaded.
data-if="path"
Include this element only when the value is truthy. Shown unconditionally when no data is loaded — so the full layout is always visible during authoring.
data-if-not="path"
The inverse: include only when the value is falsy. Combine with data-if on a sibling to form an if/else pair.
invoice.lpdf.xml 
<stack gap="m">

  <!-- scalar value with inline fallback -->
  <text data-value="invoice_number">
    INV-2026-042
  </text>

  <!-- loop: children are the sample row -->
  <stack data-source="items" gap="xs">
    <flank>
      <text data-value="description">
        Consulting Services
      </text>
      <text data-value="price">
        $1,200.00
      </text>
    </flank>
  </stack>

  <!-- conditional block -->
  <frame data-if="customer.isPremium">
    <text>Premium Customer</text>
  </frame>

</stack>
Codegen

Convert XML to typed builder code
at cursor, in any language.

Right-click an XML file in VS Code. Generated code is inserted where your cursor is. With data binding in the template, the code emits real data accessors — not placeholder strings.

🟦 TypeScript
🟣 C#
🐍 Python
🐘 PHP

The language is specified explicitly via the command palette — not guessed from the active file extension. Generated code lands at the cursor. Import statements can be prepended automatically. Running the command with no active editor opens the output in a new untitled document.

Generated TypeScript — data-source loop 
// lpdf: Generate TypeScript from XML
kit.stack({ gap: 's' },
  ...data.items.map(item =>
    kit.flank({},
      kit.text({}, item.description),
      kit.text({}, item.price)
    )
  )
)

// data-if becomes a ternary spread
...(data.customer.isPremium ? [
  kit.frame({ background: 'gold' },
    kit.text({}, 'Premium Customer')
  )
] : [])
