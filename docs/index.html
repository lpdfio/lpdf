PDF layout without

lpdf is a declarative XML layout language for PDFs. Describe your document with semantic layout primitives — Stack, Flank, Grid — and get a PDF back. No coordinate math. No boilerplate.

The problem

Stop doing arithmetic.
Start describing layout.

Every PDF library makes you think in points and absolute positions. lpdf lets you think in layout intent.

invoice.lpdf.xml after 
<lpdf version="1">
  <document size="a4" margin="28pt">
    <pages><page>
      <stack gap="m">

        <!-- title + date, right-aligned -->
        <flank align="center" end="true">
          <text size="l" weight="bold">Invoice #1234</text>
          <text color="text-muted">2024-01-15</text>
        </flank>

        <divider thickness="xs" color="#e0e0e0"/>

        <!-- table header -->
        <split gap="m">
          <text weight="bold">Item</text>
          <cluster gap="l" justify="end">
            <text weight="bold">Qty</text>
            <text weight="bold">Price</text>
          </cluster>
        </split>

      </stack>
    </page></pages>
  </document>
</lpdf>
Layout primitives

A vocabulary you already know

Inspired by modern CSS layout — if you think in flexbox, you already know lpdf.

<stack>
Stack
Vertical column. Children placed top-to-bottom with configurable gap, alignment, and space distribution.
gap="m" justify="between" align="center"
<flank>
Flank
One child fills available width; the other takes its natural size. Perfect for headers with a logo and date.
end="true" align="center"
<split>
Split
Two children share available width. Equal halves or natural + fill. Great for sidebar + main layouts.
equal="true" align="stretch"
<cluster>
Cluster
Horizontal flow with optional wrapping. Tag groups, chip sets, and badge rows — anything that can wrap.
wrap="true" gap="s" justify="start"
<grid>
Grid
N-column equal-width grid. Children placed left-to-right, row-by-row. Ideal for metric cards and image grids.
cols="3" gap="m"
<frame>
Frame
Single-child constrained container with optional max width. Use for centered inset boxes and image placeholders.
width="l" padding="m" radius="s"
<divider>
Divider
Horizontal or vertical rule. Renders a line at configurable thickness and color. No children.
direction="horizontal" thickness="xs"

FAQ

Common questions

Can I evaluate lpdf before buying?
Yes. Build with it freely under AGPL. A commercial license is only required when you ship to production in a revenue-generating context.
What is the watermark on unlicensed builds?
A small made with lpdf.io label appears in the bottom-right corner of every page — 7pt Helvetica, light gray, with a link. It is injected by the core engine and cannot be removed without a commercial license.
Does lpdf replace my PDF library?
No. lpdf takes XML and returns a PDF — the adapter is bundled. You don't need a PDF library and you don't wire anything up. Just give it a layout description.
What if my revenue grows into the next tier?
Upgrade at your next annual renewal. No retroactive charges.
Does lpdf work with HTML-to-PDF workflows?
No — and that's intentional. lpdf is not html2pdf. We don't spin up a browser and we don't try to render the web. lpdf works from an explicit layout description, for documents with known structure. If you need to capture a web page as a PDF, Puppeteer or Playwright is the right tool. If you need to produce an invoice, a certificate, or a label without coordinate math, lpdf is.
Does one license cover all my applications?
Yes. One company license covers unlimited use across all your products and services. Pricing is per company, not per application or developer.
